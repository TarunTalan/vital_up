# VitalUp - Play Store Release & CI/CD Guide

This guide covers everything configured for production deployment, CI/CD automation, Shorebird OTA code push, Firebase Analytics, and code obfuscation.

---

## 1. Secrets & Environment Configuration (Envied)

API keys and secrets are protected using **Envied** with compile-time XOR obfuscation.

### Files:
- `.env`: Local development environment variables (**gitignored**).
- `.env.example`: Safe template file committed to git.
- `lib/core/config/env.dart`: Strongly-typed obfuscated class; `env.g.dart` is generated by `envied_generator` and **gitignored** (CI regenerates it from the `ENV_FILE` secret).
- `lib/core/config/supabase_config.dart`: Backward-compatible bridge delegating to `Env` (committed; holds no values).

Only publishable client values belong here (Supabase publishable key, Mapbox `pk.` token, Google web client id). XOR obfuscation only slows down extraction; server secrets (Gemini, Groq, Resend, FCM) stay in Supabase secrets. Restrict the Mapbox token to the app in the Mapbox dashboard.

### To regenerate after updating `.env`:
```bash
dart run build_runner build --build-filter="lib/core/config/**"
```

## 2. Firebase Analytics

Integrated alongside Firebase Crashlytics & Messaging via `AnalyticsService` (`lib/core/monitoring/analytics_service.dart`).

### Features:
- **Automatic Screen Tracking**: Hooked into GoRouter via `AnalyticsService.observer`.
- **User Identification**: Automatically tracks Supabase user IDs (non-PII) via `AnalyticsService.watchUser()`.
- **Domain Event Helpers**:
  - `logWorkoutCompleted(...)`
  - `logFoodScanned(...)`
  - `logWaterIntake(...)`
  - `logVitaInteraction(...)`
  - `logAchievementUnlocked(...)`
- **Graceful Fallback**: Disabled in debug mode and safely no-ops if Firebase is not yet configured on the target platform.

## 3. Code Obfuscation & Android Production Build

VitalUp employs a two-tier obfuscation and size-reduction strategy:

### A. Dart Bytecode Obfuscation & Symbol Stripping
Removes all class names, method names, and source identifiers from Dart bytecode:
```bash
flutter build appbundle --release \
  --obfuscate \
  --split-debug-info=build/app/outputs/symbols
```
The symbols directory (`build/app/outputs/symbols`) is archived in CI (90 days) and uploaded to Crashlytics with
`firebase crashlytics:symbols:upload` when the `FIREBASE_SERVICE_ACCOUNT_JSON` secret is set. Without it, obfuscated Dart
crashes show as unreadable frames. Manual upload for a local build:
```bash
firebase crashlytics:symbols:upload --app=<mobilesdk_app_id for com.vitalup.app> build/app/outputs/symbols
```
The Crashlytics Gradle plugin (applied with `google-services.json`) uploads the R8 `mapping.txt` during release builds, and
`ndk.debugSymbolLevel = SYMBOL_TABLE` puts native symbols in the AAB for Play Console.

### B. Android R8 / ProGuard Minification & Resource Shrinking
Configured in `android/app/build.gradle.kts`:
- `isMinifyEnabled = true`: Strips unused Java/Kotlin code and obfuscates class/method names.
- `isShrinkResources = true`: Removes unused drawables and assets from external libraries.
- `proguard-rules.pro`: Keeps critical native reflection interfaces intact for ML Kit, Isar, Drift, Mapbox, JustAudio, Firebase, and Shorebird.

## 4. Shorebird Code Push (Over-The-Air Patches)

Shorebird allows you to push instant Dart code updates directly to user devices without waiting for Google Play review.

### Initial Setup:
1. Install Shorebird CLI:
   ```powershell
   iwr -useb https://raw.githubusercontent.com/shorebirdtech/install/main/install.ps1 | iex
   ```
2. Log in and initialize:
   ```bash
   shorebird login
   shorebird init
   ```
3. Update `app_id` in `shorebird.yaml`.

### Release vs. Patch Workflow:
- **New Release (Store submission)**: only Shorebird-built releases can be patched, so tag pushes always use Shorebird.
  ```bash
  shorebird release android --flutter-version=3.44.3 -- --obfuscate --split-debug-info=build/app/outputs/symbols
  ```
- **Instant Hotfix (OTA without app store review)**: Dart-only changes. Native code, Gradle, manifest, assets
  declared in pubspec and plugin version changes need a new store release.
  ```bash
  shorebird patch android --release-version=1.0.0+3 -- --obfuscate --split-debug-info=build/app/outputs/symbols
  ```
- Bump `version:` in `pubspec.yaml` (name and `+build`) before every store release; the release workflow fails if the
  tag (`v1.0.1` or `v1.0.1+2`) doesn't match it.

## 5. GitHub Actions Workflows

Three workflows have been configured in `.github/workflows/`:

| Workflow | File | Trigger | Purpose |
|---|---|---|---|
| **CI** | `ci.yml` | Push & PR to `main`/`develop` | Runs analysis, unit/widget tests, smoke debug build |
| **Play Store Release** | `play_store_release.yml` | Push git tag `v*` or Manual Dispatch | Tests, builds obfuscated Shorebird AAB, refuses debug-signed bundles, uploads symbols to Crashlytics, uploads to Play (draft by default) and GitHub Releases |
| **Shorebird Patch** | `shorebird_patch.yml` | Manual Dispatch (`workflow_dispatch`) | Builds and deploys instant OTA patch to users |

## 6. Required GitHub Repository Secrets

Configure the following secrets in **GitHub > Repository Settings > Secrets and variables > Actions**:

| Secret Name | Description | How to obtain |
|---|---|---|
| `ENV_FILE` | Complete contents of production `.env` | Copy from production environment |
| `KEYSTORE_BASE64` | Base64-encoded `vitalup-release-key.jks` | `[Convert]::ToBase64String([IO.File]::ReadAllBytes("android/app/vitalup-release-key.jks"))` |
| `KEY_PROPERTIES` | Contents of `android/key.properties` | Keystore password, keyAlias, etc. |
| `GOOGLE_SERVICES_JSON_BASE64` | Base64-encoded `google-services.json` | Downloaded from Firebase Console |
| `SHOREBIRD_TOKEN` | Shorebird CI Authentication token | Run `shorebird login:ci` |
| `PLAY_STORE_JSON_KEY` | *(Optional)* Google Play Service Account JSON | Google Play Console > Users and permissions > invite the service account (Release apps) |
| `FIREBASE_SERVICE_ACCOUNT_JSON` | *(Optional, recommended)* Service account with the Firebase Crashlytics Admin role | Google Cloud Console > IAM > Service accounts > Keys |

`ENV_FILE`, `KEYSTORE_BASE64`, `KEY_PROPERTIES` and `GOOGLE_SERVICES_JSON_BASE64` are required: the release and patch
workflows stop instead of falling back to `.env.example` or the debug key. Keep an offline backup of the upload keystore
and its passwords.

## 7. Google Play Console Pre-Launch Checklist

### Build
- [x] **Target SDK 36 & minSdk 26** (API 36 is required for new apps and updates since 31 Aug 2026).
- [x] **R8 + Dart obfuscation**, release signing enforced in CI.
- [x] **allowBackup="false"** (health data and session tokens are not backed up to Google Drive).

### First upload (manual, once)
- [ ] Create the app in Play Console with package `com.vitalup.app` (cannot be changed later).
- [ ] Enrol in **Play App Signing** and upload the first AAB by hand on the **Internal testing** track; the API
      (and the workflow) can only upload after that. Keep `release_status: draft` until the app is published.
- [ ] Personal developer accounts created after Nov 2023 must run a **closed test with 12+ testers for 14 days**
      before production access is granted.

### Keys and sign-in (package was renamed to `com.vitalup.app`)
- [ ] Copy the **App signing key** and **Upload key** SHA-1/SHA-256 from Play Console > Test and release > App integrity.
- [ ] Add both SHA-1s to the Firebase Android app `com.vitalup.app`, then re-download `google-services.json` and update
      the `GOOGLE_SERVICES_JSON_BASE64` secret. The old `com.tarun_siddhi.vital_up` client can be deleted.
- [ ] Create a Google Cloud **Android OAuth client** for `com.vitalup.app` with the Play App Signing SHA-1 (and the upload
      key SHA-1 for sideloaded builds). Without it Google Sign-In fails only on Play-installed builds.

### App content declarations
- [ ] **Privacy policy**: `https://vitalup.live/privacy`; **account deletion**: `https://vitalup.live/delete-account`.
- [ ] **Health apps declaration** and **Health Connect** permission declaration (read only: sleep, heart rate, resting HR,
      HRV, SpO2, blood pressure, steps, weight, exercise, distance, calories).
- [ ] **Usage Access** (`PACKAGE_USAGE_STATS`) permission declaration with a video of the screen time feature.
- [ ] **Foreground service** declaration for `location` (GPS workout tracking) with a demo video.
- [ ] **Data safety** form: location, health and fitness, photos (food scanner), app activity / diagnostics
      (Firebase Analytics, Crashlytics), name, email, user ids; data is encrypted in transit and users can request deletion.
- [ ] Content rating questionnaire, target audience (13+ to match the DOB rule), ads (none), news app (no).
- [ ] Store listing: icon 512x512, feature graphic 1024x500, at least 2 phone screenshots, short and full description.
